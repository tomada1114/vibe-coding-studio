## 実装の注意事項

### テスト駆動開発(TDD)のアプローチ

各タスクの実装時には、以下のTDDサイクルに従うこと:

1. **Red**: 最初に失敗するテストを書く
2. **Green**: テストをパスする最小限のコードを書く
3. **Refactor**: コードの品質を向上させる

### コミット戦略

- 各メジャータスク(1, 2, 3...)の完了時にコミットを作成する
- コミットメッセージは日本語で、「feat:」「test:」などのプレフィックスを使用する
- コミット前に`npm run check:all`を実行し、すべてのチェックに合格することを確認する

### 品質基準

- テストカバレッジ: 80%以上
- TypeScript厳格モード: すべてのコードで型エラーゼロ
- ESLint: 警告とエラーゼロ
- Prettier: すべてのコードをフォーマット済み

### パフォーマンス目標

- LCP(Largest Contentful Paint): < 2.5秒
- CLS(Cumulative Layout Shift): < 0.1
- FID(First Input Delay): < 100ミリ秒
- 初期バンドルサイズ: < 500KB(gzip圧縮後)
