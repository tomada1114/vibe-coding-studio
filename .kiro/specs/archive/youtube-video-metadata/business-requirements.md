# YouTube動画メタデータ管理システム 要件定義書（例：非エンジニアが作成したのでエンジニア観点で要チェック）

## 1. 背景と目的

### 1.1 背景
YouTube動画の概要欄は、視聴者にとって重要な情報源であり、以下のような要素を含む:
- 動画の内容説明
- 学べる内容の箇条書き
- 関連動画へのリンク
- SNSやコミュニティへの誘導
- Udemy講座などの商品誘導
- タイムスタンプ

これらの情報は動画ごとに異なるが、構造やフォーマットには一定のパターンが存在する。
しかし、現状では各動画の概要欄を個別に管理しており、以下の課題がある:

- **一貫性の欠如**: 同じ情報（SNSリンク、共通文言など）を毎回手動でコピペしており、更新漏れが発生
- **構造の不統一**: 概要欄の構成が動画によってバラバラになりがち
- **データの再利用困難**: 過去の動画データを検索・参照しにくい
- **品質チェックの困難**: 必須項目の漏れや記述ミスを発見しにくい

### 1.2 目的
本システムは、YouTube動画のメタデータを構造化されたTypeScriptファイルとして管理することで、以下を実現する:

1. **データの一元管理**: 動画情報をGitで管理し、履歴管理・変更追跡を可能に
2. **一貫性の保証**: 共通データ（SNS、Discordなど）を外部化し、全動画で統一
3. **品質保証**: TypeScriptの型システムにより、必須項目の漏れやデータ構造の誤りを防ぐ
4. **検索・参照の容易化**: 構造化されたデータにより、過去の動画情報を簡単に検索・参照
5. **概要欄生成の効率化**: データから概要欄テキストを自動生成（将来的に）

## 2. 概要

YouTube動画の概要欄とメタデータをTypeScriptファイルとして管理し、一覧・詳細表示を行うシステム。
データはGitベースでファイル管理するため、管理画面は不要。
型チェックとテストにより、データの整合性を自動的に検証する。

## 3. データ管理方針

### 3.1 基本方針
- **1動画 = 1 TypeScriptファイル**
- データはすべてGitで管理（手動編集）
- 管理画面は実装しない
- 型定義により、データの整合性を保証
- **型チェック（tsc）とテストで自動検証**

### 3.2 ファイル構成
ファイル構成は実装者に委ねるが、以下の要素は必要:

- 動画データファイル（複数）: 各動画のメタデータを含むTypeScriptファイル
- 共通データファイル: SNS、Discord、エンゲージメントなどの全動画共通データ
- 型定義ファイル: データ構造を定義する型

**推奨構成例**（参考）:
```
/data
  /videos
    video-001.ts
    video-002.ts
    video-003.ts
  /shared
    common-sections.ts
  types.ts
```

### 3.3 品質保証の方針
- **TypeScriptの型チェック**: `tsc --noEmit` で全動画データの型エラーを検出
- **テストによる検証**: 全動画データを読み込み、必須項目の存在や配列の型を検証
- **1動画ごとにテストは書かない**: 全動画データに対して共通のバリデーションロジックを実行
- **CI/CDでの自動実行**: PRやコミット時に型チェック・テストを自動実行

## 4. データ構造要件

### 4.1 必須項目
以下の項目は全動画で必須:

- **title**: 動画タイトル（string）
- **publishedAt**: 公開日時（ISO 8601形式）
- **videoUrl**: YouTube動画URL
- **opening**: 冒頭セクション（配列）
- **learningPoints**: 学べる内容セクション（配列）
- **timestamps**: タイムスタンプ（配列）
- **tags**: ハッシュタグ（配列）

### 4.2 オプション項目
動画の内容に応じて任意で追加:

- **relatedVideos**: 関連動画セクション（配列）
- **udemyCourses**: Udemy講座誘導セクション
- **customSections**: 任意の追加セクション（配列）

### 4.3 共通データとして外部化する項目
全動画で固定のため、別ファイルで管理:

- **social**: SNSアカウント情報
- **discordCommunity**: Discordコミュニティ情報
- **engagement**: エンゲージメント促進文言

## 5. 配列が必要な要素

以下の要素は可変長のため、必ず配列として定義すること:

### 5.1 必須の配列
- **opening.lines**: 冒頭セクションの各行（string[]）
- **learningPoints.items**: 学べる内容の箇条書き（string[]）
- **timestamps.items**: タイムスタンプリスト（配列）
- **tags**: ハッシュタグリスト（string[]）

### 5.2 オプションの配列
- **relatedVideos.videos**: 関連動画リスト（配列）
- **udemyCourses.courses**: 講座名リスト（string[]、オプション）
- **social.accounts**: SNSアカウントリスト（配列）
- **customSections**: カスタムセクションリスト（配列）

## 6. 型定義の設計方針

### 6.1 基本原則
- TypeScriptの型定義で構造を明確化
- 必須・オプションを `?` で明示
- 配列要素は適切に型付け
- コメントで各項目の意味を説明

### 6.2 実装の自由度
以下の点は実装者の判断に委ねる:

- **型の分割粒度**: 細かく分けるか、シンプルにまとめるか
- **ネスト構造の深さ**: フラットにするか、階層的にするか
- **命名規則**: わかりやすければOK
- **共通データの参照方法**: import方式、関数方式など
- **ファイル配置**: ディレクトリ構成は自由

### 6.3 推奨事項
- 動画データは1ファイルにまとまっている方が管理しやすい
- 共通データは別ファイルで管理し、参照する形が望ましい
- 型定義ファイルと実データファイルは分離

## 7. テスト・型チェックの要件

### 7.1 型チェック
TypeScriptの型システムを活用し、以下を自動検証:

```bash
# すべての動画データの型エラーを検出
tsc --noEmit
```

**検出すべきエラー:**
- 必須項目の欠落
- 型の不一致（string/number/配列など）
- 未定義のプロパティ
- オブジェクト構造の誤り

### 7.2 テストによる検証
1動画ごとにテストは書かず、**全動画データに対して共通のバリデーションロジック**を実行:

```typescript
// 疑似コード例
describe('全動画データの検証', () => {
  const allVideos = loadAllVideoData(); // すべての動画データを読み込み

  allVideos.forEach((video) => {
    test(`${video.title} のデータ検証`, () => {
      // 必須項目の存在確認
      expect(video.title).toBeTruthy();
      expect(video.publishedAt).toMatch(/^\d{4}-\d{2}-\d{2}T/);
      expect(video.videoUrl).toMatch(/^https:\/\/(youtu\.be|youtube\.com)/);

      // 配列の検証
      expect(Array.isArray(video.opening.lines)).toBe(true);
      expect(video.opening.lines.length).toBeGreaterThan(0);
      expect(Array.isArray(video.learningPoints.items)).toBe(true);
      expect(video.learningPoints.items.length).toBeGreaterThan(0);
      expect(Array.isArray(video.timestamps.items)).toBe(true);
      expect(video.tags.length).toBeGreaterThan(0);

      // タイムスタンプの形式検証
      video.timestamps.items.forEach((ts) => {
        expect(ts.time).toMatch(/^\d{2}:\d{2}$/);
        expect(ts.label).toBeTruthy();
      });

      // オプション項目が存在する場合の検証
      if (video.relatedVideos) {
        expect(Array.isArray(video.relatedVideos.videos)).toBe(true);
      }
      if (video.udemyCourses) {
        expect(video.udemyCourses.cta.url).toBeTruthy();
      }
    });
  });
});
```

**検証すべき内容:**
- 必須項目の存在
- 配列が空でないこと
- URL形式の妥当性
- 日付形式の妥当性
- タイムスタンプ形式（"00:00"）の妥当性
- 文字列が空でないこと

### 7.3 CI/CDでの自動実行
- **PRやコミット時**: 型チェックとテストを自動実行
- **エラー検出時**: マージをブロック
- **実行コマンド例**:
  ```bash
  npm run typecheck  # tsc --noEmit
  npm test          # テスト実行
  ```

## 8. 概要欄の構造パターン

### 8.1 基本構成（推奨順序）
1. **冒頭セクション**（必須）
   - 3-5行程度
   - 最初の125文字が最重要（展開前表示）

2. **学べる内容セクション**（必須）
   - タイトル: 絵文字 + テキスト（例: "💡 この動画で学べること"）
   - 箇条書き項目: ✅ で始まる

3. **カスタムセクション**（オプション）
   - 動画ごとに自由に追加可能
   - 例: おすすめ対象者、補足説明、環境構築など

4. **関連動画**（オプション）
   - タイトル: 絵文字 + テキスト（例: "📌 関連動画"）
   - 各動画: 絵文字 + タイトル + URL

5. **Udemy講座誘導**（オプション）
   - タイトル: 絵文字 + テキスト（例: "🚀 体系的に学びたい方へ"）
   - 説明文（オプション）
   - 講座リスト（オプション）
   - CTA: テキスト + URL

6. **SNS・コミュニティ**（必須、共通データ参照）
   - タイトル: 絵文字 + テキスト（例: "🔗 SNS・コミュニティ"）
   - アカウントリスト: X、note、Qiita、Zenn

7. **Discordコミュニティ**（オプション、共通データ参照）
   - タイトル: 絵文字 + テキスト
   - 説明文
   - URL

8. **タイムスタンプ**（必須）
   - タイトル: 絵文字 + テキスト（例: "⏰ タイムスタンプ"）
   - 各項目: 時間（"00:00"形式） + ラベル

9. **エンゲージメント促進**（必須、共通データ参照）
   - タイトル（オプション）
   - メッセージ
   - CTA文言

### 8.2 区切り線の使用
各セクション間に区切り線を入れる:
```
━━━━━━━━━━━━━━━━
```

## 10. カスタムセクションの仕様

### 10.1 目的
動画ごとに任意のセクションを自由に追加できる仕組み

### 10.2 想定される使用例
- **おすすめ対象者**: 箇条書きリスト
- **補足説明・テンプレート**: テキスト + コードブロック
- **環境構築リンク**: リンク集
- **実践データ**: テキスト + 数値データ
- **注意事項**: テキスト

### 10.3 実装方針
- セクションの型は柔軟に設計
- テキスト、リスト、リンク、混合型に対応
- 実装者が使いやすい形で設計すること

## 11. 表示機能の要件

### 11.1 一覧ページ
- 全動画のタイトル、公開日を表示
- 公開日順（新しい順）でソート
- 各動画の詳細ページへのリンク

### 11.2 詳細ページ
- 動画タイトル、公開日、YouTube埋め込み
- 概要欄を整形して表示
  - セクションごとに視覚的に区切る
  - リンクはクリック可能に
  - 箇条書きは適切にフォーマット
- タグをリスト表示

## 12. 技術的な考慮事項

### 12.1 データの読み込み
- TypeScriptファイルからデータをimport
- 共通データも同様にimport
- ビルド時に静的にデータを取り込む

### 12.2 型安全性
- TypeScriptの型定義で構造を保証
- 必須項目の漏れを防ぐ
- オプション項目を明確化

### 12.3 拡張性

- 共通データの更新が全動画に反映される
- 動画データの追加は1ファイル作成するだけ

## まとめ

このシステムは、YouTube動画のメタデータを構造化して管理することで、概要欄の一貫性を保ちながら、柔軟な拡張を可能にします。

**重要なポイント:**
1. **背景と目的**: データの一元管理、一貫性・品質の保証、効率化
2. **必須・オプション・配列の区別を明確に**: 型システムで保証
3. **共通データは外部化して再利用**: SNS、Discord、エンゲージメント
4. **カスタムセクションで柔軟性を確保**: 動画ごとの独自セクション
5. **TypeScriptの型安全性を活用**: 型チェックで必須項目の漏れを防ぐ
6. **テストで自動検証**: 全動画データに対して共通ロジックを実行
7. **実装の詳細は実装者に委ねる**: ファイル構成、型の分割など

**品質保証の仕組み:**
- `tsc --noEmit` で型エラーを検出
- テストで必須項目・配列・形式を検証
- CI/CDで自動実行し、エラーをマージ前に検出

この要件定義をベースに、実装者が使いやすく、保守しやすいシステムを構築してください。
