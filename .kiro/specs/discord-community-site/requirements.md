# Requirements Document

## Project Description (Input)

既存のデザインを参考にDiscordコミュニティ関連のサイトにしたい。

### 詳細仕様（community-lp.md より）

**プロジェクト名**: Vibe Coding Studio コミュニティサイト

**目的**:
AI駆動開発を学ぶ仲間が集まり、情報を共有し合い、一緒に成長するDiscordコミュニティへの誘導を目的としたランディングページ

**サイト構成**:
- トップページ（/）
- コミュニティページ（/community）

**デザイン方針**:
- 絵文字を使わず、かっこいいアイコンを活用
- 既存のリポジトリのデザインを踏襲
- ロゴファイル（public/logo.png、public/logo-wide-bg-black.png）を活用

**主な機能要件**:

1. **トップページ（/）**
   - ファーストビュー: キャッチコピーとコミュニティ参加ボタン
   - 工事中セクション: 準備中コンテンツの告知
   - とまだのプロフィール紹介
   - フッター: コミュニティとメディアリンク

2. **コミュニティページ（/community）**
   - ヒーローセクション: Discord参加への強いCTA
   - 3つの価値提案（仲間と繋がる、最新検証、気軽に質問）
   - コミュニティの説明
   - チャンネル紹介
   - 参加者の声（3名分）
   - FAQ（アコーディオン形式）
   - 最終CTA: Discord参加ボタン

**技術要件**:
- Next.js 15 + TypeScript
- Tailwind CSS v4
- レスポンシブ対応（スマホ: 1カラム、タブレット: 2カラム、PC: 3カラム）
- 定数管理（lib/constants.ts）

**重要な定数**:
- DISCORD_INVITE_URL: https://discord.gg/qZDRagzbVD
- SOCIAL_LINKS: Twitter, YouTube, Qiita, note, Udemy

## Requirements

### 要件1: トップページのファーストビュー表示
**目的:** Webサイト訪問者として、ファーストビューでVibe Coding Studioの価値とDiscordコミュニティへのアクセスを即座に理解したい。それにより、コミュニティ参加の意思決定を迅速に行える。

#### 受入基準

1. WHEN 訪問者がトップページ（/）にアクセスした THEN システムSHALL キャッチコピーとコミュニティ参加ボタンを含むファーストビューを表示する
2. WHERE ファーストビュー内 THE システムSHALL Vibe Coding Studioのロゴ（public/logo.pngまたはpublic/logo-wide-bg-black.png）を視覚的に目立つ位置に配置する
3. WHEN ファーストビュー内のコミュニティ参加ボタンがクリックされた THEN システムSHALL コミュニティページ（/community）へ遷移する
4. WHERE ファーストビューセクション THE システムSHALL レスポンシブデザインを適用し、スマホ・タブレット・PC環境で適切に表示する

### 要件2: トップページの工事中セクション表示
**目的:** サイト訪問者として、今後提供される予定のコンテンツを把握したい。それにより、サイトの将来的な価値と再訪する理由を理解できる。

#### 受入基準

1. WHEN 訪問者がトップページを閲覧した THEN システムSHALL 準備中コンテンツを告知する工事中セクションを表示する
2. WHERE 工事中セクション THE システムSHALL 絵文字を使わず、かっこいいアイコンで視覚的に表現する
3. IF トップページがスマートフォンで表示された THEN システムSHALL 工事中セクションを1カラムレイアウトで表示する
4. IF トップページがタブレットで表示された THEN システムSHALL 工事中セクションを2カラムレイアウトで表示する
5. IF トップページがPC環境で表示された THEN システムSHALL 工事中セクションを3カラムレイアウトで表示する

### 要件3: トップページの「とまだ」プロフィール紹介
**目的:** 訪問者として、コミュニティの主催者である「とまだ」のプロフィールを知りたい。それにより、コミュニティの信頼性と専門性を判断できる。

#### 受入基準

1. WHEN 訪問者がトップページを閲覧した THEN システムSHALL 「とまだ」のプロフィール紹介セクションを表示する
2. WHERE プロフィール紹介セクション THE システムSHALL 絵文字を使わず、アイコンと画像を活用して視覚的に表現する
3. WHERE プロフィール紹介セクション THE システムSHALL レスポンシブデザインを適用し、デバイスに応じて最適なレイアウトで表示する

### 要件4: トップページフッターのリンク表示
**目的:** 訪問者として、コミュニティと関連メディアへのアクセス手段をフッターで確認したい。それにより、複数のチャネルでコミュニティと繋がれる。

#### 受入基準

1. WHEN 訪問者がトップページを閲覧した THEN システムSHALL フッターセクションにコミュニティリンクとメディアリンクを表示する
2. WHERE フッターセクション THE システムSHALL Discordコミュニティリンク（DISCORD_INVITE_URL: https://discord.gg/qZDRagzbVD）を含める
3. WHERE フッターセクション THE システムSHALL ソーシャルメディアリンク（Twitter、YouTube、Qiita、note、Udemy）を定数管理（lib/constants.ts）から取得して表示する
4. WHEN フッター内のリンクがクリックされた THEN システムSHALL 対応する外部サイトを新しいタブで開く

### 要件5: コミュニティページのヒーローセクション表示
**目的:** コミュニティページ訪問者として、ヒーローセクションでDiscord参加への強力なCTAを確認したい。それにより、即座にコミュニティに参加できる。

#### 受入基準

1. WHEN 訪問者がコミュニティページ（/community）にアクセスした THEN システムSHALL ヒーローセクションを表示する
2. WHERE ヒーローセクション THE システムSHALL Discord参加への強いCTA（Call to Action）ボタンを目立つ位置に配置する
3. WHEN ヒーローセクション内のCTAボタンがクリックされた THEN システムSHALL Discord招待URL（DISCORD_INVITE_URL）へ遷移する
4. WHERE ヒーローセクション THE システムSHALL レスポンシブデザインを適用し、全デバイスで最適に表示する

### 要件6: コミュニティページの価値提案セクション表示
**目的:** コミュニティページ訪問者として、3つの主要な価値提案を理解したい。それにより、コミュニティ参加のメリットを具体的に把握できる。

#### 受入基準

1. WHEN 訪問者がコミュニティページを閲覧した THEN システムSHALL 3つの価値提案（仲間と繋がる、最新検証、気軽に質問）を表示する
2. WHERE 価値提案セクション THE システムSHALL 各価値提案をアイコンと説明文で視覚的に表現する
3. IF コミュニティページがスマートフォンで表示された THEN システムSHALL 価値提案を1カラムレイアウトで表示する
4. IF コミュニティページがタブレットで表示された THEN システムSHALL 価値提案を2カラムレイアウトで表示する
5. IF コミュニティページがPC環境で表示された THEN システムSHALL 価値提案を3カラムレイアウトで表示する

### 要件7: コミュニティページのコミュニティ説明セクション表示
**目的:** 訪問者として、Vibe Coding Studioコミュニティの特徴と活動内容を理解したい。それにより、コミュニティが自分に合うかを判断できる。

#### 受入基準

1. WHEN 訪問者がコミュニティページを閲覧した THEN システムSHALL コミュニティの説明セクションを表示する
2. WHERE コミュニティ説明セクション THE システムSHALL AI駆動開発を学ぶ仲間が集まる場所であることを明示する
3. WHERE コミュニティ説明セクション THE システムSHALL 「とまだ」の最新検証を見ながら一緒に成長できる環境であることを説明する

### 要件8: コミュニティページのチャンネル紹介セクション表示
**目的:** 訪問者として、Discordコミュニティ内のチャンネル構成を事前に理解したい。それにより、参加後の活動イメージを明確にできる。

#### 受入基準

1. WHEN 訪問者がコミュニティページを閲覧した THEN システムSHALL チャンネル紹介セクションを表示する
2. WHERE チャンネル紹介セクション THE システムSHALL 各チャンネルの目的と活用方法を説明する
3. WHERE チャンネル紹介セクション THE システムSHALL アイコンを活用してチャンネルを視覚的に区別する

### 要件9: コミュニティページの参加者の声セクション表示
**目的:** 訪問者として、既存参加者の実際の声を確認したい。それにより、コミュニティの雰囲気と実際の価値を第三者視点で理解できる。

#### 受入基準

1. WHEN 訪問者がコミュニティページを閲覧した THEN システムSHALL 参加者の声セクションに3名分のテスティモニアルを表示する
2. WHERE 参加者の声セクション THE システムSHALL 各テスティモニアルに参加者名・所属・コメントを含める
3. IF コミュニティページがスマートフォンで表示された THEN システムSHALL テスティモニアルを1カラムレイアウトで表示する
4. IF コミュニティページがタブレットで表示された THEN システムSHALL テスティモニアルを2カラムレイアウトで表示する
5. IF コミュニティページがPC環境で表示された THEN システムSHALL テスティモニアルを3カラムレイアウトで表示する

### 要件10: コミュニティページのFAQセクション表示
**目的:** 訪問者として、コミュニティに関するよくある質問と回答をアコーディオン形式で確認したい。それにより、疑問を効率的に解消できる。

#### 受入基準

1. WHEN 訪問者がコミュニティページを閲覧した THEN システムSHALL FAQセクションをアコーディオン形式で表示する
2. WHEN 訪問者がFAQ項目をクリックした THEN システムSHALL 対応する回答を展開表示する
3. WHEN 訪問者が展開済みのFAQ項目を再度クリックした THEN システムSHALL 回答を折りたたんで非表示にする
4. WHERE FAQセクション THE システムSHALL レスポンシブデザインを適用し、全デバイスで操作可能にする

### 要件11: コミュニティページの最終CTAセクション表示
**目的:** コミュニティページ訪問者として、ページ最下部でDiscord参加ボタンを再度確認したい。それにより、コンテンツを全て確認した後に即座に参加できる。

#### 受入基準

1. WHEN 訪問者がコミュニティページの最下部に到達した THEN システムSHALL 最終CTAセクションにDiscord参加ボタンを表示する
2. WHEN 最終CTAセクション内のDiscord参加ボタンがクリックされた THEN システムSHALL Discord招待URL（DISCORD_INVITE_URL）へ遷移する
3. WHERE 最終CTAセクション THE システムSHALL ヒーローセクションのCTAと視覚的に一貫性のあるデザインを適用する

### 要件12: 定数管理システムの実装
**目的:** 開発者として、Discord招待URLやソーシャルメディアリンクを一元管理したい。それにより、メンテナンス性を向上し、変更時の修正箇所を最小限にできる。

#### 受入基準

1. WHEN システムが初期化された THEN システムSHALL lib/constants.tsファイルで全定数を一元管理する
2. WHERE lib/constants.ts THE システムSHALL DISCORD_INVITE_URL（https://discord.gg/qZDRagzbVD）を定義する
3. WHERE lib/constants.ts THE システムSHALL SOCIAL_LINKS（Twitter、YouTube、Qiita、note、Udemy）を定義する
4. WHEN コンポーネントが外部URLを参照する THEN システムSHALL lib/constants.tsから定数をインポートして使用する

### 要件13: レスポンシブデザインの実装
**目的:** 訪問者として、使用するデバイスに関わらず最適な表示で閲覧したい。それにより、スマートフォン・タブレット・PCのいずれでも快適に利用できる。

#### 受入基準

1. IF サイトがスマートフォン（画面幅 < 768px）で表示された THEN システムSHALL 全コンテンツを1カラムレイアウトで表示する
2. IF サイトがタブレット（画面幅 768px - 1023px）で表示された THEN システムSHALL 該当コンテンツを2カラムレイアウトで表示する
3. IF サイトがPC環境（画面幅 >= 1024px）で表示された THEN システムSHALL 該当コンテンツを3カラムレイアウトで表示する
4. WHERE 全ページ THE システムSHALL Tailwind CSS v4のレスポンシブユーティリティクラスを使用する

### 要件14: デザインシステムの一貫性維持
**目的:** 開発者として、既存のRadiantテンプレートデザインシステムを踏襲したい。それにより、サイト全体の視覚的一貫性を保ち、メンテナンス性を向上できる。

#### 受入基準

1. WHERE 全ページ THE システムSHALL 既存のRadiantテンプレートのデザイントークンとコンポーネントを再利用する
2. WHERE 全ページ THE システムSHALL 絵文字を使わず、Heroiconsまたは類似のアイコンライブラリを使用する
3. WHERE ロゴ表示箇所 THE システムSHALL public/logo.pngまたはpublic/logo-wide-bg-black.pngを使用する
4. WHERE 全UIコンポーネント THE システムSHALL Headless UIとCatalyst UIコンポーネントパターンに準拠する

### 要件15: 技術スタックの遵守
**目的:** 開発者として、プロジェクトで定められた技術スタックを使用したい。それにより、既存のRadiantテンプレートとの互換性とメンテナンス性を保証できる。

#### 受入基準

1. WHERE 全実装 THE システムSHALL Next.js 15のApp Routerを使用する
2. WHERE 全実装 THE システムSHALL TypeScript厳格モードで型安全性を確保する
3. WHERE スタイリング THE システムSHALL Tailwind CSS v4とPostCSSを使用する
4. WHERE コンポーネント実装 THE システムSHALL 既存の/src/componentsディレクトリのコンポーネントを最大限活用する
5. WHERE ページ実装 THE システムSHALL /src/app/ディレクトリにpage.tsxとして実装する
