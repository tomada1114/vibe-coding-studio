# 実装計画: カスタムコマンド公開機能（TDD方式）

## 概要

カスタムコマンド公開機能の実装タスク一覧です。この計画では、**TDD（テスト駆動開発）アプローチ**に従い、各機能について「テスト作成 → 実装 → リファクタリング」のサイクルで開発を進めます。

**TDDの原則**:
1. **Red（失敗するテストを書く）**: 実装前に期待する振る舞いをテストで定義
2. **Green（テストを通す最小限の実装）**: テストをパスする最小限のコードを書く
3. **Refactor（リファクタリング）**: コードの品質を向上させる

## TDD実装サイクルの詳細

各機能の実装では、以下のTDDサイクルを厳守します：

### 🔴 Red フェーズ（失敗するテストを書く）
1. **期待する振る舞いを明確にする**: 要件から具体的なテストケースを抽出
2. **最小限のテストを書く**: 1つの振る舞いに集中したテストを作成
3. **テストを実行する**: テストが失敗することを確認（まだ実装がないため）
4. **失敗の理由を確認する**: エラーメッセージが期待通りか検証

### 🟢 Green フェーズ（テストを通す最小限の実装）
1. **テストをパスする最小限のコードを書く**: 完璧を目指さず、まず動かす
2. **テストを実行する**: すべてのテストが通ることを確認
3. **早すぎる最適化を避ける**: パフォーマンスよりも正確さを優先

### 🔵 Refactor フェーズ（リファクタリング）
1. **コードの品質を向上させる**: 重複排除、命名改善、構造の最適化
2. **デザインシステムに準拠**: Radiant のスタイルガイドラインを適用
3. **テストを実行する**: リファクタリング後もすべてのテストが通ることを確認
4. **コミット**: クリーンな状態でコミットする

## 実装時の注意事項

### 1. TDD原則の厳守
- **テストファースト**: 実装前に必ずテストを書く
- **小さなステップ**: 一度に1つの機能に集中する
- **継続的なリファクタリング**: テストがパスしたら即座にコードを改善する

### 2. デザインシステム遵守
- すべてのコンポーネントは Radiant デザインシステム（`docs/design/`）の原則に従う
- カラーパレット: Gray-950、Gray-700、Gray-600 を主体とする
- 余白: 8pxグリッドシステムに基づく
- タイポグラフィ: 見出し 36px/24px、本文 16px

### 3. 型安全性
- TypeScript 厳格モードで `any` 型の使用を避ける
- すべての関数に明示的な型注釈を追加する
- フロントマターの型はランタイムバリデーションで補完する

### 4. 既存パターンの踏襲
- `/videos` ページと同様のルーティングとデータローダーパターンを使用する
- Container、Navbar、Footer などの既存コンポーネントを再利用する
- AsyncErrorBoundary で一貫したエラーハンドリングを実装する

### 5. エラーゼロトレランス
- コミット前にすべてのエラーを修正する
- `npm run check:all` を実行してlint、type-check、testをすべてパスする
- console.log文は本番コードから削除する

### 6. 頻繁なコミット
- 各TDDサイクル（Red → Green → Refactor）完了後にコミットする
- コミットメッセージは従来の形式（feat:、test:、refactor:）を使用する
- 小さく原子的なコミットを心がける

### 7. テストカバレッジ
- コアロジック（CommandLoader）: 100% カバレッジを目指す
- UIコンポーネント（CommandCard、CopyButton）: 主要な振る舞いをカバー
- ページコンポーネント: 統合テストで重要なユーザーフローをカバー

### 8. パフォーマンス意識
- 初期バンドルサイズを常に監視する
- 重いライブラリ（シンタックスハイライト）は動的インポートする
- Lighthouse スコアを定期的にチェックする

## タスク実行の推奨順序

TDD方式に従い、以下の順序で実装を進めることを推奨します：

1. **基盤準備** (タスク1) → テストデータとインフラの準備
2. **CommandLoader** (タスク2) → Red → Green → Refactor
3. **CommandCard** (タスク3) → Red → Green → Refactor
4. **一覧ページ** (タスク4) → Red → Green → Refactor
5. **CopyButton** (タスク5) → Red → Green → Refactor
6. **CodeBlock/CommandDetail** (タスク6) → Red → Green → Refactor
7. **詳細ページ** (タスク7) → Red → Green → Refactor
8. **最終調整** (タスク8) → パフォーマンス・アクセシビリティ
9. **デプロイ準備** (タスク9) → 最終検証
