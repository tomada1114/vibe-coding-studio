# スキルの書き方

**扱う:** `.claude/skills/*/SKILL.md` の frontmatter・構造・サイズ・境界宣言の書式、
新しいスキルを起こすかどうかの判断、`.agents/skills/` とのリンク作成手順。
**扱わない:** 個々のスキルの中身そのもの（各スキル自身が扱う）; デザイントークンや
コンポーネント規則（`geist-grid-design`）; どのチェックを走らせるか（`changing-gates`）。

## 単一の情報源

スキルは `.claude/skills/<name>/SKILL.md` に実体を置く。`.agents/skills/<name>` は
そこへの相対シンボリックリンク（`../../.claude/skills/<name>`）で、Codex CLI がスキルを
見つける入口になる。**片方だけを編集することはない** — 実体は常に `.claude/skills/` 側で、
`.agents/skills/` はリンクを張るだけ。新しいスキルを追加したら:

```bash
ln -sfn "../../.claude/skills/<name>" ".agents/skills/<name>"
```

同期スクリプトは存在しない。リンクが正しく張られているかは `__tests__/skills.test.ts` が
機械的に検査する（後述）。

## frontmatter

キーは `name` と `description` の **2 つだけ**。

- `name`: ディレクトリ名と完全に一致させる。
- `description`: 折り畳みブロックスカラー（`>` または `|`）で書く。素のスカラー行に
  `": "` が含まれると Codex CLI 側のパーサが壊れることがあるため、必ずブロックスカラーにする。
  内容は「何を扱うスキルか」+ 発火条件を示す `Use when ...` の一文。既存スキルの
  `description` を見本にする。

`metadata:` のような追加キーは置かない。`.agents/skills/` にリンクを張る以上、
全スキルが両プラットフォーム対応であることは構造上の前提であり、
プラットフォームを宣言するキーは冗長になる。

## 本文の形

1 行目は必ず `# <スキルのタイトル>`。その直後に境界宣言を置く:

```markdown
**扱う:** <このスキルが責任を持つ変更の種類>。
**扱わない:** <隣接スキルが持つ範囲>（`skill-name`）; <別の隣接>（`skill-name`）。
```

隣接スキルは**名前で指す。パスや見出しで指さない** — ディレクトリを移動しても
壊れないようにするため。境界宣言のあとは自由な構成でよいが、既存スキルの見出しの
粒度（`##` を大きな話題ごとに、必要なら `###` で細分）に合わせる。

相互参照のマーカーは 2 つだけ使う:

- `**必読:** <skill>` — そのスキルを読まないと自分のタスクが終えられない。
- `**背景:** <skill>` — 理由や経緯の説明だけで、読まなくても作業は進められる。

## サイズ

目標 150 行、上限 200 行。超えそうなら、独立して読める塊を別スキルに分ける
（分けたら双方に境界宣言を書き、`AGENTS.md` のスキル表にも行を足す）。
既存の `geist-grid-design`（約 290 行）は移行前からの唯一の例外として残っている —
新しいスキルの言い訳には使わない。

## AGENTS.md に書くか、スキルに書くか

`AGENTS.md` はタスクの種類が決まる**前**に真でなければならないことだけを持つ
（プロジェクトの形、承認規約、どのスキルを読むべきか）。ある種類の変更に手を付けた
**あとで**初めて要る手順や判断は、スキルに書く。迷ったら:

- 「どのファイルを触るときでも当てはまるか」→ 当てはまるなら `AGENTS.md`。
- 「特定の種類の変更に手を付けたときだけ要るか」→ そうならスキル。
- 設定ファイル（`jest.config.js` の閾値、`.npmrc` のクールダウン日数など）が持つ**値**は
  どちらにも書き写さない。スキルからは「強制: `<ファイル>` の `<設定名>`」のように
  1 行で指すだけにする。値を転記すると、転記した側が先に古くなる。

## AGENTS.md のスキル表との整合

`AGENTS.md` の `## スキル` 節にある表は、全スキルの一覧であり発火の入口でもある。
新しいスキルを追加したら、この表に 1 行足す。`__tests__/skills.test.ts` が
双方向でずれを検出する: 表に無いスキルディレクトリがあれば失敗し、表にあるのに
実在しないディレクトリを指す行があっても失敗する。

## `__tests__/skills.test.ts` が検査すること

新しいスキルを書いたら、以下を満たしているか確認する（このテストは `src/` を対象にせず
`jest.config.js` のカバレッジ閾値には影響しない）:

1. `.claude/skills/<dir>/SKILL.md` が各ディレクトリに 1 つだけ存在する。
2. frontmatter のキーが `name` と `description` の 2 つだけ。
3. `name` がディレクトリ名と一致する。
4. `description` が空でない。
5. 本文に `**扱う:**` と `**扱わない:**` の両方がある。
6. `AGENTS.md` のスキル表に全スキルの行がある。
7. その表の各行が実在するディレクトリを指す。
8. `.agents/skills/<name>` が `.claude/skills/<name>` への正しいシンボリックリンクである。
